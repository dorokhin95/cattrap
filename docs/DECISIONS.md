# Журнал архитектурных решений (ADR) — CatTrap

## ADR-001: Выбор технологического стека Phaser 3 + TypeScript + Vite
- **Контекст:** Требуется 2D trap-платформер с честной физикой, адаптивной камерой, fixed timestep 60 FPS, сценами и поддержкой Web / Telegram Mini App.
- **Решение:** Использовать Phaser 3 в связке с TypeScript и Vite.
- **Обоснование:** Phaser 3 предоставляет готовые механизмы Arcade Physics с фиксированным шагом (`fixedStep`), сцены, тайлмапы, эмиттеры частиц, развитую систему камер и событий, идеально подходя под требования ТЗ (раздел 54).

---

## ADR-002: Процедурный синтез звуков через WebAudio API
- **Контекст:** Игра должна быть максимально лёгкой для Telegram Mini App (< 4–5 МБ) и гарантировать мгновенный запуск без ожидания загрузки аудиофайлов.
- **Решение:** Процедурный синтез ретро-звуковых эффектов (квадратные, треугольные волны, шум) и фонового chiptune-лупа непосредственно в WebAudio API.
- **Обоснование:** Нулевой вес аудиоассетов, отсутствие сетевых задержек, отсутствие проблем с блокировкой CORS, мгновенная реакция при взаимодействии.

## ADR-003: Процедурная генерация пиксель-арта на Canvas
- **Контекст:** Кот должен иметь характерный силуэт (крупная голова, уши с выемкой, хвост-вопросительный знак с тёмным кончиком, ошейник, светлая мордочка) и плавно анимироваться (Idle, Run, Jump, Fall, Landing, Death, Portal).
- **Решение:** Процедурный генератор текстур `PixelArtGenerator`, создающий растровые пиксель-арт полотна на HTML5 Canvas при старте в `BootScene` и передающий их в Phaser TextureManager.
- **Обоснование:** Автономность, отсутствие битых картинок, возможность масштабирования с `pixelArt: true`, мгновенная загрузка.

## ADR-004: Детерминированная модель триггеров ловушек
- **Контекст:** ТЗ строго запрещает рандом и непредсказуемость. Игрок должен стабильно проходить уровень, выучив принцип ловушки.
- **Решение:** Все триггеры базируются на дискретных координатах игрока (`player_x`, `player_y`), событиях касания (`onContact`) или последовательных очередях с фиксированным интервалом (`delay: 120ms`).
- **Обоснование:** 100% повторяемость условий гибели и победы вне зависимости от частоты кадров.

## ADR-005: Уменьшенный Lethal Hitbox опасных объектов
- **Контекст:** Касание крайнего пикселя ловушки не должно приводить к гибели котика.
- **Решение:** Смертельный коллайдер шипов и падающих блоков составляет 65–75% от их визуальной площади, а физический коллайдер котика — 14×19 px при размере спрайта 24×24 px.
- **Обоснование:** Исключает ощущение несправедливой гибели («пиксель-перфект»).

## ADR-006: Единая кодовая база для Web и Telegram Mini App
- **Контекст:** Требуется поддержка GitHub Pages, мобильных/десктопных браузеров и Telegram Mini App.
- **Решение:** Слой `PlatformService` (`BrowserPlatformService` и `TelegramPlatformService`) с полиморфным интерфейсом.
- **Обоснование:** Устраняет дублирование кода, гарантируя одинаковое поведение физики и уровней на всех платформах.

## ADR-007: Мультитач и эргономичное сенсорное управление (Touch Controls)
- **Контекст:** На мобильных устройствах игроки играют двумя большими пальцами (левый — бег, правый — прыжок). По умолчанию Phaser 3 слушает только 1 указатель (`activePointers: 1`), что приводило к потере управления прыжком во время бега. Кроме того, дискретные круглые кнопки направления приводили к срыву бега при естественном смещении пальца.
- **Решение:**
  1. В `main.ts` явно сконфигурирован `input: { activePointers: 3 }`.
  2. D-Pad переработан в непрерывную рокерную сенсорную зону (184×84 px, хитбокс 220×120 px) с вычислением направления по отклонению пальца от центра (`diff = pointer.x - dpadCenterX`) и поддержкой события `pointermove` без отрыва пальца.
  3. Кнопка прыжка `JUMP` увеличена до диаметра 92 px с расширенной круговой зоной касания 150 px и мгновенным визуальным scale/color фидбеком и вибрацией (Haptics).
- **Обоснование:** Обеспечивает комфортный и отзывчивый отклик платформера при игре на сенсорных экранах смартфонов любого размера.
